## 测试与支持

### 支持环境

- Windows x64
- Blender 4.2.0 - 5.2.0（含 5.2.0）
- Adobe Photoshop 桌面版 CC2017 - 2026（含 2026）

| 操作系统 | Windows 11 25H2 | Windows 10 22H2 |
| CPU | AMD R9 7950X 十六核 | AMD R5 3600 六核 |
| GPU | NVIDIA RTX 4060 Ti 16GB | NVIDIA RTX 2060 6GB |
| 内存 | 32GB * 2 | 16GB * 2 |

| Photoshop | CC2017 18.1.6 | 2020 21.2.1 | 2022 23.5.0 | 2025 26.10.0 | 2026 27.7.0 |

## 测试内容

测试模式为：

使用个人常用版本 Blender 5.1.2 + Photoshop 2025 26.10.0 进行插件开发，直到版本稳定后，再对 Blender 的 4.2.21 LTS 和 5.2.0 LTS 版本进行测试，确保核心功能与关联链路能够稳定运行。

之后在另一台机器上，对各版本 Blender 和 Photoshop 重新进行矩阵测试。矩阵测试主要用于检查不同 Blender、Python 和 Photoshop 版本之间容易出现差异的代码路径，包括项目协议、跨软件通信、状态切换、文件写回、撤销以及项目隔离等内容。

测试素材均存放于本地磁盘的项目目录，包含：

- 1 份 5 个图层的简单结构 PSD 文档；
- 1 份 4 个图层的小型复杂结构 PSD 文档；
- 1 份 49 个图层的复杂结构 PSD 文档；
- 1 份包含 49 个 2D 面片、骨骼、动画的真实 Blender 工程。

### 1. 环境与通信协议

测试开始前会确认当前实际运行的 Blender、Photoshop 和插件版本，并检查：

- 插件 Manifest、运行时代码与随附 Photoshop JSX Bridge 的版本一致性；
- Blender 插件声明的版本支持范围；
- 当前实际连接的 Photoshop 版本与安装路径；
- Job、Result、Association、Project、Layout、Import Plan、Import Analysis 等核心通信协议；
- Blender 与 Photoshop 两端所需的协议能力与任务状态字段；
- Photoshop 完成任务后，由插件正式结果读取与验证流程确认任务终态；
- 各 Blender 版本加载的是同一份待发布插件内容。

### 2. JSON、多贴图资产与核心往返流程

- JSON 与独立贴图能够正常导入；
- 按贴图生成正确数量的矩形 Mesh；
- Blender Mesh、Image、项目 Part 与 Photoshop Smart Object 保持完整映射；
- UID、贴图文件、尺寸、位置、四角方向和排列关系正确；
- Photoshop 工作文档能够通过正式项目创建流程生成并保持为当前工作文档；
- 从已提交项目导出 PhotoshopToSpine JSON，导出项数量与项目 Mesh 数量一致，`images` 路径能够解析对应项目贴图；
- **编辑单一贴图** 能够打开正确的项目贴图，并由 Photoshop 实际修改和保存；
- Blender 手动刷新后，Image Buffer 能读取新的图像内容；
- **应用待合并图层** 能实际改变对应项目贴图；
- **分配待合并图层** 与 **对单图层分配** 能实际改变对应项目贴图；
- 应用和分配完成后，新图层能够进入正确的 Photoshop 归档位置；
- Undo 能精确恢复受影响的项目贴图，并将归档图层按原 Layer ID 和顺序恢复；
- 工作 PSD 在连续编辑、应用、分配和撤销过程中保持正常打开与保存；
- 完成整个往返流程后，Blender、项目包与 Photoshop 之间的项目映射仍然有效。

### 3. PhotoshopToSpine 与 Spine Region Attachment

静态 JSON 兼容功能测试，包括：

- PhotoshopToSpine 风格 JSON 与独立贴图的正式导入；
- 根据 JSON 生成对应数量和布局的矩形面片；
- 从已提交 Blender 项目导出 PhotoshopToSpine 静态 JSON；
- 检查导出 JSON 中的贴图数量和 `images` 路径；
- 使用标准 Spine JSON 导入静态 Region Attachment；
- 根据 Setup Pose 创建对应矩形面片；
- 导入过程中保持原始 JSON 与贴图素材不变。

### 4. 自动刷新

在 Photoshop 中实际修改当前项目贴图并保存，由插件自身注册的后台 Timer 检测文件变化。

主要验证以下内容：

- 自动刷新 Timer 正常注册；
- 被修改贴图的 Blender Image Buffer 自动更新；
- 不调用手动刷新 Operator 也能够完成刷新；
- 未修改的其他项目贴图保持不变；
- 自动刷新完成后，全部 Part 的 Blender、项目包与 Photoshop 映射保持一致。

### 5. 打开已有项目

- Photoshop 工作文档能够正常重新打开；
- Blender 项目 Collection、Mesh、Image 与项目身份正确恢复；
- 全部 Part 映射重新建立；
- 重复打开同一项目不会重复创建 Blender 资源；
- 项目文件不会因为单纯的重新打开而发生变化；
- 当前工作文档和项目状态保持正确。

### 6. 多项目切换

建立两个独立项目 A 和项目 B，并执行 B → A → B 的双向切换。

主要验证以下内容：

- 两个项目分别使用独立的 Blender Collection 和项目资产；
- 创建项目 B 不会修改项目 A；
- 切换后当前项目身份和 Photoshop 工作文档正确更新；
- 非当前项目的文件和 Blender 数据保持完整；
- 多次切换后两个项目的完整 Part 映射仍然有效；
- 一个项目的操作不会污染另一个项目。

### 7. 项目副本独立化

对复制后的项目包执行 **使项目副本独立** 所使用的核心事务，并主动构造三种 Smart Object 链接状态：

- 所有 Smart Object 已指向候选副本中的贴图；
- Smart Object 同时存在父项目与候选项目链接；
- Smart Object 错误链接到两个项目之外的第三方文件。

主要验证以下内容：

- 候选副本获得新的独立项目身份；
- 父项目身份和文件保持不变；
- 候选项目协议更新到新的项目身份；
- 需要迁移的 Smart Object 实际重新链接；
- 项目协议、工作文档和贴图路径全部指向候选项目目录；
- 候选项目重新建立完整的 Part 映射；
- 事务结束后项目锁、事务状态、临时备份和恢复状态正确清理。

在遇到第三方错误链接时，则验证以下内容：

- Photoshop 任务以 `FAILED` 结束并返回 `LINK_MISMATCH`；
- 错误信息能够定位对应图层和实际链接路径；
- 候选 Photoshop 文档及项目协议保持不变；
- 父项目保持不变；
- 不遗留项目锁、事务状态、临时备份或恢复状态。

### 8. PSD / PSB 文档导入

- PSD 与 PSB 的实际文件格式正确；
- Photoshop 能重新打开生成的基准文档；
- 源文档在分析和导入过程中保持不变；
- 插件能够得到完整的图层分析结果；
- 图层 ID、层级路径、图层类型、可见性、画布尺寸和 Bounds 与 Photoshop 侧观察结果一致；
- 隐藏图层按设置正确忽略；
- 默认 **统一简化** 能将复杂图层组处理为确定的导入结果；
- 内置基准最终形成 3 个导入贴图；
- 导入计划、实际导出的 PNG、项目 Part 与 Blender Mesh 数量相互一致；
- 导出 PNG 包含实际可见像素；
- 普通图层的输出贴图尺寸与 Photoshop Bounds 对应；
- Blender Mesh 的尺寸和布局与 Photoshop 文档构图对应；
- 项目工作文档保持正确的画布尺寸和 PSD / PSB 格式；
- 项目所需的 Photoshop 图层组结构正确建立。

### 9. JPG、TGA 与日常辅助工具

- JPG、TGA 的正式 JSON 导入、图像绑定和尺寸；
- TGA Alpha 信息；
- 根据导入记录恢复被删除的材质和图像；
- 同步未连接的同名 Shader 参数；
- 安全合并插件生成且未经修改的重复材质；
- 在同名目标格式文件已经存在时切换贴图格式，并同步更新 Image 与导入元数据。

### 10. UI 与公开接口合同

- 核心公开 Operator 的注册、标题和说明；
- 日常工作流 Scene Property 的存在性、默认值与枚举内容；
- VIEW_3D 插件 Panel 的注册状态；
- 核心中英文 UI 文本及格式化模板；
- UI 所依赖的关键公开接口在版本更新后保持完整。
