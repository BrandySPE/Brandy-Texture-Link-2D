## 测试与支持

当前测试模式为：

使用个人常用版本 Blender 5.1.2 + Photoshop 2025 26.10.0 进行插件开发，直到版本稳定后，再对 Blender 4.2.21 LTS 和 5.2.0 LTS 进行手动测试，确保核心功能与关联链路能够正常运行。

之后对实机安装的各版本 Blender 和 Photoshop，重新进行全面的矩阵测试。详细的测试内容请看下文。

测试素材来自真实项目文件，至少包含 1 份 5 个图层的简单结构 PSD 文档、1 份 49 个图层的复杂结构 PSD 文档、1 份 49 个 2D 面片的 Blender 文件。测试素材均存放于本地磁盘的项目目录。

### 测试内容

1. 环境与协议身份验证

- 插件 Manifest ID 与运行时模块身份；
- Manifest、插件运行时及随附 Photoshop JSX Bridge 的版本一致性；
- 插件安装内容指纹；
- Blender 插件声明支持范围；
- Photoshop 通信后端及当前实际 Photoshop 身份；
- Photoshop COM Observer 实际应用版本与安装路径；
- 插件所需 Job、Result、Association、Project、Layout、Import Plan 等通信协议合同；
- Photoshop 任务结果通过插件正式结果读取与验证链完成终态确认。

2. JSON / 多贴图资产导入与核心往返流程

- JSON 与独立贴图导入；
- 按贴图生成正确数量的矩形 Mesh；
- 创建 Photoshop 项目；
- 项目部件数量验证；
- Blender Mesh、Image、项目包 Part 与 Photoshop Smart Object 的完整映射；
- UID、文件路径、尺寸、位置、四角方向及顺序一致性；
- 从已提交项目导出 PhotoshopToSpine JSON；
- 导出 JSON 中贴图数量和 images 路径有效性；
- 编辑选中贴图入口；
- Photoshop 中修改实际贴图像素；
- Blender 手动刷新后 Image Buffer 实际发生变化；
- 恢复源文件后 Blender Image Buffer 恢复；
- 应用多图编辑后实际源贴图字节发生变化；
- Photoshop 测试图层正确归档；
- Undo 后源贴图与 Photoshop 工作文档恢复至应用前完全相同的 SHA-256；
- 原始输入素材在整个往返过程中保持只读。

3. Spine Region Attachment 有限导入

使用标准 Spine Region JSON 与碎图素材验证有限兼容模式，包括：

- Spine Region Attachment JSON 正式导入入口；
- 两张贴图正确生成两个矩形面片；
- 输入素材保持未修改。

4. 自动刷新

验证 Photoshop 修改项目贴图后，在不调用手动刷新 Operator 的情况下：

- 自动刷新 Timer 正式注册；
- 被修改贴图的 Blender Image Buffer 自动更新；
- 未修改的其他项目贴图保持不变；
- 项目全部 Part 的 Blender - 项目包 - Photoshop 映射保持一致。

5. 打开已有项目

验证通过插件公开入口重新打开已有 Brandy Texture Link 2D 项目，包括：

- Photoshop 工作文档实际打开；
- Blender 项目 Collection、Mesh、Image 与项目绑定信息恢复；
- 全部 Part 映射恢复；
- 重复打开同一项目具有幂等性，不重复生成 Blender 资源；
- 打开过程中不修改项目包文件；
- 操作结束后无残留文档启动辅助进程。

6. 多项目切换

建立两个独立项目 A 与项目 B，并验证：

- 两个项目使用独立 Blender Collection；
- 创建项目 B 不修改项目 A；
- B → A 切换后当前正式项目正确变更为 A；
- 非当前项目 B 保持完整且文件不被修改；
- A → B 再次切换后当前正式项目正确变更为 B；
- 非当前项目 A 保持完整；
- 两个项目在 Blender、项目包和 Photoshop 中的完整映射始终有效。

7. 项目副本独立化 / Fork

验证项目文件夹复制后，插件将副本独立化为新项目的核心事务，测试包括三种实际智能对象链接状态：

- 全部 Smart Object 已链接至候选副本贴图；
- 父项目贴图与候选项目贴图混合链接；
- Smart Object 错误链接至项目目录之外的第三方文件。

成功场景验证：

- 候选副本获得新的项目身份；
- 父项目身份保持不变；
- 父项目文件保持字节不变；
- 候选项目协议与项目身份发生实际更新；
- Photoshop Smart Object 按需重新链接；
- 项目协议、工作文档和贴图路径全部指向候选项目目录；
- Blender 当前项目仍保持父项目；
- 项目锁、事务状态、临时备份及待恢复状态在事务完成后全部清理。

错误链接场景要求插件必须确定性拒绝操作：

- Photoshop 任务终态必须为 FAILED；
- 错误码必须为 LINK_MISMATCH；
- 错误信息必须能够指出相关图层及父项目、候选项目和实际链接路径；
- 候选 Photoshop 文档和项目协议不得发生修改；
- 不得留下项目锁、事务标记、临时备份或待恢复状态；
- Blender 当前项目不得被错误切换。

8. PSD / PSB 文档导入

每个 Blender 版本均使用 QA 在当前 Photoshop 中实际生成并冻结的确定性 PSD 与 PSB 基准执行测试，验证内容包括：

- Photoshop 实际生成 PSD 与 PSB；
- 文件头 8BPS 格式验证；
- PSD format version = 1；
- PSB format version = 2；
- Photoshop 能重新打开生成的基准文档；
- 原始文档及测试工作副本保持字节不变；
- 项目工作文档保持与源文档一致的 PSD/PSB 实际格式；
- 插件图层分析结果非空；
- 图层 ID、路径、图层类型、可见性和画布尺寸与独立 Photoshop Observer 结果交叉核对；
- 导入计划、导出 PNG、项目 Part、Blender Mesh 数量相互一致；
- 导出贴图实际像素尺寸与 Photoshop 图层 Bounds 相符；
- Blender Mesh 的尺寸和布局与文档图层位置对应；
- 项目工作文档画布与源文档一致；
- 插件保留组数量及结构有效；
- 内置复杂文档的默认统一简化策略符合确定性基准。

9. 日常辅助工具

验证以下工具的实际结果，而非仅验证 Operator 可以被调用：

- 根据导入记录恢复被删除的材质及图像；

## 安全设计

1. **打开详细报告** 中可找到任务失败的原因、部分任务的执行细节，以及报错后的解决办法，为日常使用中的检查与排错提供渠道。

2. 在 **手动脚本** 模式下，您的操作会生成对应的脚本文件，之后您可在 Photoshop 中通过 `文件` > `脚本` 手动运行，可确保插件能在特殊环境下提交工作。

3. 插件面板中设计多个隐藏按键，可为不同任务的意外中断提供重连、恢复、清理等操作，详情可见 [用户指南](用户指南.md) 中的 `其他细节` 章节。

4. 插件自身不进行任何网络通信，也不依赖云端服务，项目文件、任务协议、备份和诊断信息均在本地处理。Photoshop、操作系统、云同步软件等宿主环境可能存在网络行为，不属于插件的控制范围。

5. 在任务执行时，插件会在不同阶段完成以下检测或处理：

- 对 Photoshop 启动项的身份校验。
- 对项目进行交叉检查，避免因缺少文件、身份不一致、哈希值不符、未完成项目等情况干扰运行。
- 对项目路径和目录边界进行检查，避免路径过长或非法路径。
- 从图层名、对象名或资产名生成文件名时，插件会检测非法字符和控制字符等内容，避免非法路径。
- 对 JSON 文件进行作业 ID、请求和结果协议版本、项目锁版本及能力等信息进行验证，并在 Photoshop 写完结果后生成 result.ready，确保写入任务稳定。
- 项目锁会记录 Blender 实例 ID、进程 PID、可获取时的进程启动时间等信息，避免未知项目写入。
- JSON、任务状态、标记文件采用多阶段写入模式，避免直接在目标文件上逐步覆盖，尽可能确保任务因意外原因中断时不留下无效的残留。
- 破坏性操作前会建立可验证备份。
- 创建项目和 PSD 导入时，会先建立未完成标记及状态日志。只有 Photoshop 输出和 Blender 提交均成功后，项目才转为完整状态。
- PSD 导入将外部原文档视为只读输入。插件先创建经验证的项目内归档副本，再由该副本生成独立工作文档，不在原始 PSD 或 PSB 上直接写入。
- 跨项目写入隔离。
- 点击或中断项目时，Blender 写入取消请求，由 JSX 在安全检查点响应。代码不会直接结束 Photoshop 进程。
- 诊断信息本地保存，并进行路径弱化处理。

## 使用须知

1. 贴图互通以 RGB 8 位和 sRGB 显示工作流为主要目标，不适合作为 CMYK、16 或 32 位图像或严格色彩管理母版的无损往返方案。

2. JPG 和 JPEG 作为支持格式，但不支持透明通道，并且反复保存存在有损压缩。对 sprite、角色和 billboard，优先推荐 PNG 或 TGA 格式。

3. 有效的 `2D 面片` 应当满足：

- 所有顶点位于统一二维平面，至少形成一个有效面区域，所有顶点属于同一连通区域；
- 外围只有一个闭环；外围轮廓必须是项目平面中的轴对齐矩形；外围边不得斜切或弯曲；
- 具有有效的活动 UV 层，满足连续矩形 UV 要求，且不存在局部拉伸或外围 UV 接缝；
- 可存在内部细分、三角化、矩形边上的额外共线顶点，但不允许出现内部孔洞、多个独立网格岛、一条边由三个或更多面共用的情况；
- 可存在约束、驱动器、动画和 NLA，但它们不会作为 Photoshop 往返数据。

4. 活跃项目、备份和恢复目录优先放在本机磁盘。云同步或网络目录可以使用，但同步冲突、延迟和非本地文件系统语义可能降低锁与恢复机制的可靠性。

5. 自动刷新应视为 `后台分片检查和稳定后的自动刷新`，并非零延迟同步。

自动刷新的轮询式机制为：

- 活跃状态最快间隔约 0.6 秒；
- 空闲间隔约 1.5 秒；
- 中大型项目放宽到约 2.5 或 4 秒；
- 单次扫描预算约 8 毫秒；
- 文件变化后等待约 0.35 秒确认稳定；
- 连续拓扑变化过多时会进入退避或暂停状态。
- 重新加载前进行检测与验证。

6. 部分单项按键与任务的边界如下表：

| 项目 | 代码上限或要求 | 边界说明及超出后处理方式 |
|---|---|---|
| PSD/PSB 导入单元数 | 最多 2048 项 | 包括最终导入计划中的贴图项 |
| PSD/PSB 文档宽高 | 每边最多 300,000 px | 插件安全检查上限 |
| 单张导出贴图宽高 | 每边最多 300,000 px | 实际上限通常较理论更低 |
| 归一化画布宽高 | 每边最多 300,000 px | Blender 直接建项目同样检查 |
| PSD 导出贴图总像素 | 最多 250,000,000 px | 所有输出贴图累计 |
| 透明扩边 | 0–8192 px | UI 和 JSX 双端限制 |
| 自动选择 PSB | 画布任一边超过 30,000 px | 直接创建项目时自动使用 PSB |
| 通用导入 JSON | 最大 64 MiB | 超出时阻断 |
| 取消确认等待 | 60 秒 | 不会强制终止 Photoshop |
| 结果读取重试 | 最多 5 次 | 另有约 5 秒重试窗口 |
| 自动刷新每次扫描 | 最多 32 个文件 | 单次时间预算约 8 ms |
| 自动刷新每次重载 | 最多 2 张图像 | 防止阻塞 Blender UI |
| 自动刷新失败尝试 | 最多 5 次 | 延迟约为 1、2、5、10 秒 |
